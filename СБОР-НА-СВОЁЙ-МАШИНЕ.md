# Сбор данных со своего компьютера

Зачем это нужно. Российские афиши отбивают адреса дата-центров, где работают
облачные раннеры GitHub. Проверено с их адреса:

| Сайт | Что отвечает облаку |
|---|---|
| `api.timepad.ru` | 403 Forbidden |
| `afisha.ru` | 200, но 3.6 КБ и заголовок «Один момент...» — антибот |
| `afisha.yandex.ru` | оболочка страницы, ноль карточек событий |
| `kinomax.ru` | заглушка «Верификация» |
| `kinoafisha.info` | 403 обычному запросу (настоящий браузер пока пускает) |
| `kudago.com` | работает |

С твоего домашнего адреса всё это открывается — ты обычный посетитель. Никакие
прокси и обходы защиты для этого не нужны, нужен только правильный адрес.

Есть два способа. Первый — на десять минут разово, второй — один раз настроить
и забыть.

---

## Способ 1. Двойной клик (проще)

Понадобятся [Node.js](https://nodejs.org) (кнопка LTS) и
[Git для Windows](https://git-scm.com/download/win). Оба ставятся кнопкой
«Далее» без настроек.

1. Скачай репозиторий на компьютер: зелёная кнопка **Code → Download ZIP**,
   распакуй. Или, если Git уже стоит, в командной строке:
   `git clone https://github.com/veraxxxo/cinemafinder`
2. Открой папку и запусти **`collect.cmd`** двойным кликом.

Скрипт сам обновит код, поставит что нужно, соберёт данные и отправит их в
репозиторий. Карта обновится через минуту-две после этого.

Лимиты внутри подняты, потому что с домашнего адреса торопиться некуда:
5 дат, до 80 фильмов, события на 2 недели вперёд. В облаке — 3 даты и
30 фильмов, иначе прогон не укладывается во время.

---

## Способ 2. Раннер (собирает сам, каждый час)

Тот же сбор, но запускается сам, пока компьютер включён. Настраивается один
раз.

1. Открой **Settings → Actions → Runners → New self-hosted runner**, выбери
   **Windows**. GitHub покажет готовые команды с одноразовым токеном —
   скопируй их в PowerShell как есть. Выглядят они примерно так:

   ```powershell
   mkdir actions-runner; cd actions-runner
   Invoke-WebRequest -Uri <ссылка_с_страницы> -OutFile actions-runner.zip
   Expand-Archive -Path actions-runner.zip -DestinationPath .
   ./config.cmd --url https://github.com/veraxxxo/cinemafinder --token <ТОКЕН_СО_СТРАНИЦЫ>
   ```

2. На вопросы `config.cmd` жми Enter — значения по умолчанию подходят.
3. Чтобы раннер жил после перезагрузки, поставь его службой (PowerShell от
   администратора, в той же папке):

   ```powershell
   ./svc.sh install
   ./svc.sh start
   ```

   Если `svc.sh` нет, просто запускай `./run.cmd` — он работает, пока открыто
   окно.

4. Проверь: **Settings → Actions → Runners**, статус должен быть **Idle**.

Всё. Workflow «Обновление данных (своя машина)» подхватит раннер и будет
собирать каждый час. Запустить прямо сейчас: вкладка **Actions** → этот
workflow → **Run workflow**.

### Что важно знать

**Облачный сбор остаётся.** Он не отключается и продолжает работать, когда
компьютер выключен. Это сделано намеренно: когда-то мы указали
`runs-on: self-hosted` в основном workflow, не подняв раннер, — джоба зависла
в очереди навсегда и своей группой заблокировала все остальные прогоны, включая
ночные. Поэтому домашний сбор живёт отдельным файлом.

**Накопления очереди не будет.** Если компьютер был выключен неделю, при
включении не пойдёт стопка пропущенных запусков: настройка `cancel-in-progress`
оставляет только самый свежий.

**Про безопасность.** У домашнего workflow намеренно нет триггера
`pull_request`. Репозиторий публичный, и без этого правила любой человек мог
бы прислать pull request и выполнить свой код на твоём компьютере. Если
когда-нибудь будешь добавлять туда триггеры — этот трогать нельзя.

### Если что-то не так

* раннер в статусе **Offline** — компьютер выключен или служба не запущена;
* джоба висит в очереди — раннер не подключился, смотри пункт 4;
* `node: command not found` в логе — Node не в PATH у службы; переустанови
  Node с галкой «Add to PATH» и перезапусти службу.
