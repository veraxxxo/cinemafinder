# 🎬 CinemaFinder

Карта всех кинотеатров Москвы с фильтрами по **фильму** и **времени сеанса**.
Задаёшь фильтр — видишь на карте, что где и во сколько идёт.

**Карта:** https://veraxxxo.github.io/cinemafinder/
*(включается в Settings → Pages, см. «Развёртывание»)*

---

## Что умеет

| Фильтр | Как работает |
|---|---|
| **Дата** | ближайшие 5 дней, переключается чипсами |
| **Фильм** | поиск с автодополнением, можно выбрать сразу несколько; рядом с названием — число сеансов в этот день |
| **Время** | два ползунка «с / до» + пресеты: *от сейчас*, утро, день, вечер, ночь. Ночные сеансы (00:40) считаются продолжением вечера, а не отдельным днём |
| **Кинотеатр** | поиск по названию, адресу и сети |
| **Рядом** | геолокация: список сортируется по расстоянию |

На карте остаются только кинотеатры, подходящие под фильтр; цифра на пине —
сколько там подходящих сеансов. Клик по пину — список фильмов с временами,
залом, ценой и ссылкой на покупку, плюс кнопка маршрута в Яндекс.Картах.

## Откуда данные

**Кинотеатры** — OpenStreetMap через [Overpass API](https://overpass-api.de/):
запрос `amenity=cinema` внутри границ Москвы (relation 102269, включая ТиНАО).
Это единственный источник, который даёт **координаты** — без них карты не будет.
Дубли (одна точка как нода и как здание) схлопываются.

**Расписание** — открытое API [KudaGo](https://docs.kudago.com/api/)
(`/movie-showings/`, без ключа) плюс парсер `kinoafisha.info`.

### Что показала разведка источников

Прежде чем писать парсеры, workflow «Диагностика источников» опросил
кандидатов **с IP GitHub Actions**. Результат отрезвляющий:

| Источник | Итог |
|---|---|
| `kinoafisha.info` | **403** на всех URL — режет адреса дата-центров |
| `kinomax.ru` | страница «Верификация» — антибот |
| `karofilm.ru`, `kinoteatr.ru`, `mirage.ru` | 200, но расписание рисует JS: в HTML **ноль** времён |
| `afisha.yandex.ru` | 200, 400 КБ — и ни одного сеанса в разметке |
| внутренний API Яндекс Афиши | **400** на всех вариантах — нужны сессионные параметры |
| `kassa.rambler.ru` | 404 |
| **`kudago.com/public-api`** | **работает без ключа** |

Воспроизвести: workflow «Диагностика источников» → поле «Свои URL».

### Что из этого выяснилось на практике

Разведка выше говорила «kinoafisha режет дата-центры», и это правда — для
обычного HTTP-запроса. **Настоящий Chromium она пускает.** Прогон 09.08
показал это прямо: страницы фильмов открываются на 400–1230 КБ, «Одиссея» —
40 сеансов, «Последний богатырь» — 23. Так что рабочая схема оказалась
проще, чем ожидалось: не прокси, а браузер.

Заодно проверилось и остальное:

* **Scrapling не помог.** В Actions он даже не установился: `scrapling install`
  падал с `No module named playwright`, и цепочка отключала его на первом же
  вызове. В `requirements.txt` добавлен `playwright`, но до подтверждённого
  прогона считать его рабочим нельзя;
* **kinomax по-прежнему закрыт.** Браузер получает страницу без нужной
  разметки, прямой запрос — заглушку «Верификация», все три прокси отвечают
  520 / 522 / 403. Источник остаётся в `SOURCES`, но даёт ноль;
* **общего расписания города больше нет.** `/russia/msk/schedule/` отвечает
  404 и браузеру, и напрямую. Стратегия убрана: она дарила каждому прогону
  около четырёх минут на заведомо безнадёжные повторы через прокси;
* **KudaGo** работает, но покрытие частичное — курируемая афиша, а не полный
  агрегатор;
* в попапе каждого кинотеатра есть **прямые ссылки** на Яндекс Афишу и Кино
  Афишу по названию — туда, где расписание заведомо полное.

Парсер kinoafisha идёт по страницам отдельных фильмов: на каждой перечислены
все залы города с временами. Страницы грузятся по четыре одновременно
(`KA_CONCURRENCY`). Если страница пришла живая и увесистая, а разбор пуст —
это похоже на смену вёрстки, и в дело вступает разбор моделью (нужен секрет
`GROQ_API_KEY`). Что сработало — видно в `schedule.json` → `layers`.

**Сшивка.** Афиша и OSM называют одно и то же место по-разному
(«КАРО 11 Октябрь» ↔ «Октябрь»). `fetch-schedule.mjs` сопоставляет их в три
прохода: точное совпадение нормализованных названий → вхождение подстроки →
пересечение значимых слов (порог 0.6). Если пары нет, но источник дал
координаты, площадка попадает в `extraCinemas` и всё равно рисуется на карте —
сеанс не теряется. Что не легло никуда, печатается в лог: это рабочий список
для доводки.

## Обновление

`.github/workflows/update.yml` — cron **06:25 и 16:25 МСК** плюс ручной запуск.
Джоба тянет данные, кладёт в `data/` и коммитит. Защита от порчи данных:

* меньше 50 кинотеатров из Overpass → падаем, файл не перезаписываем;
* пустое расписание при непустом предыдущем → оставляем прежнее;
* падение Overpass не мешает собрать расписание (и наоборот);
* хост, не давшийся ни одним способом дважды подряд, до конца прогона
  пропускается: перебор всей цепочки стоит около полутора минут, и на
  наглухо закрытом сайте эти минуты повторяются на каждой странице.

Chromium закрывается **один раз** в конце `fetch-schedule.mjs`. Пока он
открыт, node не завершается: 09.08 данные уже были записаны в 09:55, а шаг
провисел до таймаута в 10:01 и пометился упавшим — закрытие стояло внутри
одного источника, а следующий поднимал браузер заново.

Итог каждого запуска — в Summary джобы: сколько сеансов, фильмов, площадок,
какие уровни парсинга сработали, сколько названий не сопоставилось.

### Если расписание перестало собираться

Запусти вручную workflow **«Диагностика источников»** (`probe.yml`). Он
покажет по каждому кандидату-URL: HTTP-код, размер, `<title>`, есть ли
состояние SPA и его ключи, сколько JSON-LD блоков, сколько ссылок на
кинотеатры/фильмы и сколько строк вида `HH:MM` — и примеры тегов вокруг
времени. Этого хватает, чтобы поправить `scripts/sources/kinoafisha.mjs`.

## Локально

```bash
npm test           # 16 офлайн-проверок парсеров и сшивки, сеть не нужна
npm run probe      # что отдают источники прямо сейчас
npm run update     # собрать data/cinemas.json и data/schedule.json
npm run serve      # открыть карту на http://localhost:8080
```

Запуск `npm run update` с домашнего адреса имеет смысл: kinoafisha не режет
обычные IP, и расписание получается полнее, чем из Actions.

Зависимостей у продакшена нет — только Node 20+ (нужен встроенный `fetch`).
Фронтенд — статика: Leaflet + MarkerCluster с CDN, свой `app.js`.

### Проверка интерфейса в браузере

```bash
npm install @playwright/test
node scripts/smoke.mjs --shot smoke.png
```

Поднимает сайт на локальном порту, подменяет данные фикстурой и кликает
фильтры в настоящем Chromium: пресеты времени, ночной сеанс `00:40`,
мультиселект фильмов с автодополнением, поиск по кинотеатру, переключение
даты — 13 проверок.

### Живучесть фронтенда

* `data/` пуст → `app.js` дотягивает кинотеатры прямо из Overpass в браузере;
* расписания нет → карта показывает все кинотеатры без сеансов;
* Leaflet не загрузился с CDN → список и фильтры продолжают работать,
  в области карты выводится пояснение.


## Сбор со своего сервера (снимает все ограничения)

Сайты афиш режут адреса дата-центров, где работают облачные раннеры GitHub:
kinoafisha отвечает 403, kinomax показывает «Верификацию». Отсюда и прокси,
и браузер, и лимиты на число страниц за прогон — всё это обход, а не решение.

Решение — запускать тот же workflow на своём сервере. Тогда запросы идут
с обычного адреса: ни блокировок, ни прокси, ни ограничений.

**Один раз на сервере** (Linux, нужен Node 20+):

```bash
# Settings → Actions → Runners → New self-hosted runner — GitHub выдаст
# готовые команды с токеном, они выглядят так:
mkdir actions-runner && cd actions-runner
curl -o actions-runner.tar.gz -L https://github.com/actions/runner/releases/latest/download/actions-runner-linux-x64.tar.gz
tar xzf actions-runner.tar.gz
./config.sh --url https://github.com/veraxxxo/cinemafinder --token <ТОКЕН_ИЗ_ИНТЕРФЕЙСА>
sudo ./svc.sh install && sudo ./svc.sh start   # чтобы жил после перезагрузки
```

**Один раз в workflow:** в `.github/workflows/update.yml` заменить
`runs-on: ubuntu-latest` на `runs-on: self-hosted`, а в шаге «Расписание
сеансов» добавить `KA_DIRECT: '1'` и поднять лимиты страниц.

Раньше это переключалось переменной `RUNNER_LABEL`, но так делать нельзя:
если переменную завести, а раннер не поднять, джоба встаёт в очередь
навсегда — без ошибки, без сообщения, просто «pending». Наступили на это
и убрали. Переезд должен быть осознанной правкой, которую видно в диффе.

Проверить, что раннер жив: Settings → Actions → Runners, статус «Idle».

## Когда парсер не справился

`data/manual-schedule.csv` — источник наравне с парсерами. Формат:

```
кинотеатр;адрес;фильм;дата;время;цена;зал
Киномакс Пражская;метро Пражская, Москва;Одиссея;2026-08-08;19:30;1480;2D
```

Адрес можно указать станцией метро — по ней геокодер находит район, и зал
встаёт на карту, даже если его нет в OpenStreetMap. Это страховка на случай
редизайна сайта или новой блокировки, а не временный костыль.

## Развёртывание

Settings → Pages → **Source: GitHub Actions**. Дальше `pages.yml` публикует
сам на каждый push в `main`.

**Про видимость репозитория.** Pages с приватного репозитория работает только
на платном плане (Pro/Team): на Free сайт просто перестаёт собираться и отдаёт
404. И даже на Pro **опубликованный сайт остаётся публичным** — закрывается
исходный код, а не карта; ограничить доступ к самой странице умеет лишь
Enterprise Cloud. Плюс на приватном репозитории Actions начинают тратить
квоту минут (на публичном они безлимитны), а этот workflow ставит Chromium
дважды в сутки.

Отдельно: Pages раздаёт содержимое репозитория как файлы сайта, поэтому
`data/schedule.json` и `data/cinemas.json` скачиваются по прямой ссылке при
любой видимости репозитория.

## Добавить источник расписания

Новый файл в `scripts/sources/` с экспортами:

```js
export const id = 'мой-источник';
export const title = 'Мой источник';
export async function fetchDate(date) {
  // → { shows: [{ date, time, cinemaName, movieTitle, hall, price, url }], layer }
}
export const normalizeTitle = (t) => t.trim();
export const movieKey = (t) => slugify(t);
```

и добавить его в массив `SOURCES` в `scripts/fetch-schedule.mjs`. Сшивка
с координатами и дедупликация сеансов уже общие.

## Структура

```
index.html  app.js  style.css      карта и фильтры
data/cinemas.json                  кинотеатры с координатами (OSM)
data/schedule.json                 сеансы, фильмы, даты
scripts/fetch-cinemas.mjs          Overpass → cinemas.json
scripts/fetch-schedule.mjs         источники + сшивка → schedule.json
scripts/sources/kinoafisha.mjs     парсер афиши
scripts/probe.mjs                  диагностика источников
scripts/lib/util.mjs               fetch с ретраями, нормализация, JSON-LD
```
